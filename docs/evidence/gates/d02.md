## Required result

[GOAL §9 D02](../../../../GOAL.md#minimum-end-to-end-acceptance-scenarios):
create, read, update, delete and supported upsert/transaction operations
return the expected stored values and errors. Repeating the same idempotent
request returns the original result without a second effect; reusing its
identity for a different request is rejected according to the contract.

## Expected versus observed

- **Expected:** every supported document operation, including upsert and
  transactions, returns the documented values and errors through the deployed
  HTTPS API; exact retries have one effect; a mismatched retry is rejected;
  data survives restart.
- **Observed (R22, 2026-10-01):** the walkthrough passed 13/13 (create, exact
  retry, update, delete and their replication), on TerraBase `743c569`, which
  predates the schemaless write contract.

## Audit 2026-10-01 (not acceptance)

- The walkthrough passes 13/13 (create, exact retry, update, delete) on R16
  and R19–R22.
- Missing: upsert and transaction coverage, identity-mismatch rejection, and
  restart.
- **Contract break:** TerraBase `main` uses schemaless JSON writes since
  `dfa00c40`, but the orchestrator walkthrough still sends the old typed body.
  Lane A2 is fixing this on branch `a2/schemaless-write-consumers`.
