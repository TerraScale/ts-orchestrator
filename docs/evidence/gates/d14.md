## Audit 2026-10-01 (not acceptance)

- Live Chromium check on `gru.api.terrascale.tech` and `api.terrascale.tech`:
  `/docs` returns 200; the Scalar 1.72.1 CDN script integrity matches GOAL's
  `sha384`; the page renders with no skeleton; 4 operations are visible; an
  anonymous Test Request returns 401 directly from the API origin.
- **Resolved the same day: Cloudflare Web Analytics beacon.** The audit found
  the beacon (`static.cloudflareinsights.com`) blocked by the docs CSP, which
  fails `verify-scalar-browser.cjs`. At about 08:30 UTC `terrascale-37`
  applied, with the `cf` CLI, rule `04d059ccd04f44b3a621f4aba7c1b945` in the
  `terrascale.tech` zone's configuration-rules entrypoint ruleset
  `ca1fd87761ab4266a19c23e1de815891` (phase `http_config_settings`,
  version 1): expression
  `(http.host in {"api.terrascale.tech" "gru.api.terrascale.tech"})` with
  `set_config` `disable_rum=true`. A host exclusion in the Web Analytics
  ruleset was not possible, because the free plan allows one rule and the
  include-all `*` rule already uses it. A headless Chromium check on both
  hosts afterwards showed only the pinned script, no beacon and no CSP
  violations.
- Missing: an authorized Try-it run with a scoped credential.
- The specification is hand-written, and route coverage compares against a
  hard-coded list rather than `parse_route`.
- The browser check is not in CI.
- `/docs/protocols` does not link the `psql` or gRPC documentation.
