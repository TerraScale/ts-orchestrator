Integrated initial GRU R1 startup, 2026-09-05.
Base commit: 493f1a22.

The executable initial-gru-r1 command consumes the original owner-signed full
host manifest, root-owned proof publication and durable initial admission.
ts-node publishes before launch effects and retires before replacement effects.
Pending command recovery starts only a receiver until a fresh authenticated
retry; installed retired releases cannot be relaunched through rollback.

The seed provisions the complete regional/global profiles with distinct
provisioner and runtime identities. A second GRU process uses its own admission,
regional coordinator and signed membership against the same broker. Normal
production composition and global worker R3 requirements remain unchanged.
Initial budget: 4144234496 bytes. Seed disk: 4412669952 bytes, including a
separate 256MiB filesystem allowance. Capacity is not measured allocation.
Recovery uses exact decompressed signed bytes with unchanged 32KiB per-file
and 48KiB serialized metadata bounds. One staged fixture measured 16628 bytes
serialized, 11423-byte manifest and 11793-byte grant.

Shared global desired consumers now set Durable=Name. Real restricted R3 tests
reject named ephemeral consumers and verify exact durable readback, pull,
DoubleAck and retained acknowledgement state across reopen.

All credential use captures bounded bytes through verified directory
descriptors. The broker validates signed TLS references and removes those
references before parsing the remaining literal JSON; captured TLS material
is attached before option validation. Broker parsing cannot reopen TLS paths.
Both globalclient and initialcontrol use natsconnect for bounded DNS/TCP/
INFO/TLS/PONG setup and cancellation ownership transfer. Initial participants
exit on closed connections so systemd can restart through fresh admission.
Normal closure cannot report its own component disposal as a new failure.

- blank broker provisioning, exact restart and real-lease-derived retirement;
- insufficient budget and conflicting retained profiles fail closed;
- two independently admitted processes share one broker and publish signed
  membership; the participant cannot provision stores;

- plaintext broker configuration and swapped credential rejection;
