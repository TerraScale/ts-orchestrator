## Audit 2026-10-01 (not acceptance)

T1, not met (5.3–9.8 min):

- `publish` promotes the retained `release` bytes instead of rebuilding.
- No `SHA256SUMS` release asset.
- The binaries embed the build time and `/kache` paths.
- No scheduled clean rebuild checks reproducibility.
- The release smoke test runs only `--help` and `keygen` under qemu.

T2, not met (Fast 4m25–21m32; 4 of 11 `main` pushes failed):

- Cargo runs with `-j6` and the suite with 8 test threads on a 32-CPU runner.
- PR #166 merged tmpfs storage for RustFS.

Priority rule (§7.1), met: no `nice` or `ionice` in CI.

## T2 result 2026-10-01

Met: five consecutive TerraBase `main` push runs (#1089, #1101, #1112, #1116,
#1121) passed Fast, release and publish, with Fast at most 4m42. The three
runs after the stale-build fix (#1121, #1125, #1126) passed at 1m12, 2m26 and
2m38. Durations are Fast job times from `fj actions tasks`.

Root causes, all at a timing, readiness or isolation boundary, and their
fixes (TerraBase PRs):

| Failure class (runs) | Cause | Fix |

Speed: #187 (`5f5f0c15`) optimizes dependencies in the `dev` profile. The
suite fell from 49–160 s (263 CPU-s in #1112) to 19–24 s (85 CPU-s in #1114).
The first build after the change was cold: clippy 6m06s and test build
9m59s. Raising Cargo to 16 jobs did not shorten a workspace rebuild locally
(143–145 s against 105–112 s at 6 jobs, 2.9–4.6 GiB peak), so the cap of 6
stays. At 12–16 threads the local suite fell from 59 s to 41–46 s, but the
8-thread cap stays: with optimized dependencies the runner suite already
takes 19–24 s, and more threads would add load on the shared runner for
little gain.

Stale-build blast radius: of 48 Fast jobs from #1061 to #1108, two waited
for a Cargo slot. #1107 (PR #188, `90dc223d`) compiled no workspace unit
although it changed `tb-document` and `tb-server`, so its pass was invalid.
#1097 (PR #178) rebuilt all workspace units in its test build. No `main` run
was affected.

Open risks: PR jobs can write `/cache/kache` and the Cargo target slots that
`main` and `release` jobs reuse (cache poisoning; P4 and T1 scope). The
host's systemd user manager stopped at 16:44, so local process suites need a
restored user session.
