## Reproduce the read-only checks

1. Verify identity with `hostname`, `tailscale status --json` self fields,
   `netbird status --json` FQDN, and `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`.
2. Inventory `ip -j address`, `ip -4 -j route show table all`,
   `ip -6 -j route show table all`, and IPv4/IPv6 `ip -j rule`.
3. Inventory user and root `podman network ls --format json`, then inspect only
   network fields of running containers. Do not print container environments.
4. Check `tailscale ping --c 1 --timeout 5s PEER`, MagicDNS resolution,
   NetBird JSON status, and `timeout 5 bash -c 'exec 3<>/dev/tcp/PEER_IPV4/22'`.
5. Check `resolvectl status` where available, or `/etc/resolv.conf` resolver
   fields plus `tailscale dns status`. Read only named nonsecret NetBird fields
   (`WgIface`, `DisableDNS`, `DisableClientRoutes`, `DisableServerRoutes`).

`sudo netbird-wt0` is the enrolled peer command on delta and beta;
`sudo podman exec -i ts-netbird-ops netbird` is the enrolled peer command on
mariogk-dev. The inspected client versions need coordination with TS-674's
NetBird 0.80 ownership. No live client migration or other machine's LAN change
was performed by this audit.
