## Smallest current-source production document

config.rs:361-459 defines the closed TOML keys, parse_production:652-791 validates them. Mandatory root keys: mode="production", environment, databases, placement, transport, release. Omit local [engine], [tbep], [observability], [public_api], [replication]: they are unknown production fields. Never omit mode (absence selects local parsing).

- environment: name (1..96 ASCII alphanumeric/dot/underscore/hyphen), cluster and local member (canonical uppercase 26-character ULIDs).
- databases: minimum ONE enabled database, maximum 1024. Each requires tenant, project, database ULIDs; region GRU/SFO/FRA covered by placement; location, policy_journal, backup_root absolute distinct paths; encryption_provider exactly "oci-vault"; encryption_key canonical database-key-version ULID; quotas {max_storage_bytes:1..2^50,max_documents:1..1e9,max_inflight:1..1e6}; explicit enabled=true for at least one entry. Database IDs unique globally, scope triples unique, each project belongs to only one tenant. An empty catalog or all-disabled catalog fails. encryption_key is NOT an OCI key OCID, raw key, key file, or keyring.
- placement: generation>0, epoch>0, regions array containing 1..3 distinct supported regions. Each region has exactly TWO globally unique member ULIDs, and local member occurs exactly once. Thus the syntactic minimum is one region, two members; a three-region six-host qualification requires all three regions and six seats, not a one-member shortcut.
- transport: tbep_listen, quic_listen, metrics_listen are three different numeric IP:port sockets with nonzero ports. Concrete private guest addresses avoid wildcard opt-ins. Optional allow_wildcard_tbep/quic/metrics default false; only unspecified IP binds require true. server_certificate, server_private_key, client_ca are distinct absolute path references. peers is mandatory and exactly ALL placement members except local, each {member,endpoint,spiffe_identity}. Endpoints are unique non-wildcard nonzero IP:port sockets, unequal to local listeners. Identity must exactly equal spiffe://terrascale.tech/{environment}/terrabase-member/{clusterULID}/{memberULID}. Minimum one peer, or five for six hosts. Required numeric fields: max_message_bytes 1024..16777216; max_inflight 1..4096; request_timeout_millis and shutdown_grace_millis 100..300000; tls_handshake_timeout_millis 100..30000. A reasonable source-fixture profile is 16777216,128,30000,5000,30000 respectively. Omit uds for minimal config.
- release: release is nonempty ASCII up to128 bytes; capabilities must contain exactly production,tbep,quic,metrics,oci-vault once each. These are required configuration claims, explicitly not proof of capability or qualification. Bind release label to supplied artifact metadata; do not manufacture a supported-production claim from its hash.

All six required path references per database-plus-TLS set are pairwise distinct/non-nested across the entire configuration. Existing path components may not be symlinks or group/other writable (mode &0022=0); /tmp descendants fail because /tmp itself is writable. Paths need not exist for parse, so parser acceptance alone does not prove TLS or storage. Use e.g. /var/lib/terrabase/databases/{database}, /var/lib/terrabase/policies/{database}, /var/lib/terrabase/backups/{database}, and sibling /etc/terrabase/tls/{server.crt,server.key,ca.crt}; these are renderer layout choices, not external APIs. Actual enabled database locations must also be direct children of one common storage root in production.rs:211-242.

Config load accepts exactly --config PATH (and no other arguments), OR TERRABASE_CONFIG_FILE but never both. File must be nonempty strict UTF-8 TOML <=65536 bytes, regular, no final symlink, not group/other writable, and stable length while read (config.rs:462-536,1042-1108). Atomic owner-only file publication is appropriate.

## What qualification can generate, and what it must require

Qualification owns guest addresses, host inventory, private ports, per-host file layout, file permissions, bounded settings and argv, so it can render these directly. It may mint run-scoped cluster/member ULIDs and matching qualification-only CA/leaf keys ONLY as explicit qualification identity assignments persisted with the run; existing orchestrator host IDs and grants are not TerraBase Member ULIDs or durable membership. Its peer array can reflect those declared seats and addresses without claiming membership admission. TLS leafs must carry exact member SPIFFE URI SAN and proper peer IP SAN; use private-key files, never inline secrets. Existing orchestrator initial-R1 seeds do not provide these TerraBase inputs (seed owner confirmed).

Require authoritative or explicitly isolated qualification database scope/quotas, database-key-version identity, and placement generation/epoch. Do not generate fake tenant/project/database or Vault key identities to make a parser green. No daemon keys exist for Vault credentials, provider endpoints, durable-membership sources, keyring mutation, placement-intent mutation, or database lifecycle APIs. Adding guessed keys fails deny_unknown_fields and does not fill the missing contracts.

## Why parser success is not yet the membership diagnostic

Only after these succeed does it drain and return "no durable orchestrator membership source is configured". Reaching that diagnostic therefore requires usable owned storage, real matching TLS materials, valid transport and an available UDP endpoint, not just syntactic TOML. Catalog construction expressly opens no key provider; it does not prove OCI Vault/keyring capability. The static file is expressly not membership authority.

Preserve this as a producer input compatibility limitation; do not weaken PEM checks or claim arbitrary valid generated certificates will reach membership. ## Smallest proposed Go renderer slice

Add one internal typed production guest-config renderer beside vmcontrolseed/vmqual with RenderTerraBaseProductionConfig(input) -> bounded TOML bytes,error. Input contains run-bound artifact release, environment/cluster/member identities, explicit database/key-version records, declared RF2 placement, host address table and supplied TLS file paths. Derive exact peer list and SPIFFE identities from those inputs; validate cross-field equality, canonical identity forms, closed regions and enum values, quotas, paths and byte bound. Use a TOML encoder with explicit field tags and deterministic ordering. Renderer does not call cloud APIs, create admission records, mint database keys, or set readiness.

Guest preparation writes /etc/terrabase/server.toml owner-only from those bytes, supplies owned storage directories/TLS files through existing guest file injection, and sets TerraBase argv to ["--config","/etc/terrabase/server.toml"]. Missing required external input returns a named input error before launch. Do not apply a dummy config unconditionally. Separate verification should later execute the supplied binary in the authorized guest, record exact binary+config digest and startup result, and require the named membership component error only AFTER parser/catalog/TLS pass. This audit neither ran that check nor promises that working-tree schema matches the binary. No additional membership flag/endpoint exists to render.
