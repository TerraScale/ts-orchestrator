# TerraBase managed-member runtime contract

Status: **A and C source snapshots are frozen and accepted; B has matching Go/Rust source support but remains unqualified as an integrated managed launch**. A freezes the reviewed schema-5 placement and bounded member-status source set. C freezes the three-file mounted-volume claim/layout source set. B's Go caller supplies the pinned managed-material arguments accepted by TerraBase; startup and reload use the same pinned manifest. Existing source tests do not establish a Go-to-TerraBase managed launch on a mounted OCI guest, serving, or drain policy. These observations do not authorize production launch.

## Producer requirements still to freeze

These are semantic requirements for a future producer/consumer contract, not agreed method names or a wire schema:

* A fresh member observation must bind the process and local recovery to the exact cluster, tenant, database, shard, member, incarnation, authority epoch/configuration, certificate and host session. If it reports peer state, it must identify each certified peer and distinguish received, durable and applied frontiers for a specific origin incarnation.
* Serving must be decided from the actual client data path, its declared read/write admission, required visibility frontier and selected durability/failure-domain policy. `/readyz`, a listening port, `Welcome`, or one ACK frame is not enough. The owners still need to choose the serving predicate and its policy identity.
* Retirement needs a durable writer fence and a receipt that resolves admitted writes and required outgoing replication obligations against named surviving members. The owners still need to choose command idempotency, receipt persistence/recovery, and the order between fencing and authority change. SIGTERM or process exit is not such a receipt.
* Host reports should continue to attest only host-observed mount/process/session state. The controller must obtain any serving or survivor proof from a producer source and bind it to the same member and authority generation.

The current managed placement state demonstrates the intentional hold: after it writes desired state it enters `awaiting-healthy`, and the next controller pass holds rather than changing to `serving`. `StageServing` is also returned to `awaiting-runtime-contract` because a host process report is insufficient. `CanBeginRetirement` has a two-other-serving-members-per-selected-region safety floor; that Go floor is not evidence of TerraBase replication factor or a product quorum policy. The TerraBase certificate allows 2–64 members, while this outbound managed sender profile uses exactly two. Product owners must resolve scale-in and durability policy rather than treating either count as a quorum rule.
