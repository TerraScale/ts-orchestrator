# TerraBase managed-member runtime contract request

Status: **proposed v1 interface; no production launch authorized by this document**. This is a producer/consumer brief for the TerraBase and orchestrator owners. The current `awaiting-runtime-contract` hold remains correct until the interfaces and real-caller checks below exist. The original source inspection was on 2026-09-24; a later 2026-09-25 read found an outbound sender and emitted `AppliedAck` in mutable TerraBase source. The hashes at the end distinguish those observations. TerraBase source is largely untracked, so its Git revision alone does not identify its contents.

## Proposed versioned producer contract

The placement admission and durable member record should gain a new schema version. The v2 managed runtime boundary must reject v1 token identities and seat labels unless a separately approved, one-time migration first persists an unambiguous mapping; there is no compatibility alias path. Do not reinterpret `permanent-a`/`elastic-gru` as TerraBase `ReplicaId`. A v2 authority input should contain:

```text
scope: cluster_id (16 bytes / 32 hex), tenant_id (canonical uppercase ULID),
       database_id (canonical uppercase ULID), shard_id (uint64; > 0 for current managed replication)
placement: intent_generation, selected_regions, seat_id, failure_domain
member: member_id (canonical uppercase ULID), incarnation (nonzero 16 bytes),
        host_attempt, OCI instance/create key, retained volume/attachment IDs
authority: membership_epoch (nonzero), configuration_id (32 bytes),
           signed certificate digest, trust-key fingerprint,
           complete certified member and schema/catalog set
runtime: admitted artifact digest, bounded memory limit/headroom,
         concrete replication listen address, per-member TLS/secret references
```

The controller must allocate and CAS-persist `member_id` and the initial nonzero 16-byte `incarnation` once for a durable logical seat/retained volume **before** any OCI launch or volume effect. Host replacement and intact retained-volume recovery preserve both identities and the volume; uncertain retries or an uncertain prior writer stop also preserve them and hold activation until the old writer is proven fenced. TerraBase's `OriginId.incarnation` changes when causal history is reset, not on each host or writer attempt. A successor writer activation, including a host rebind, requires old-writer fencing and a producer-approved signed authority transition for its exact `(member_id, incarnation, TLS leaf hash, server name, failure domain)` row. A causal-history reset additionally requires that transition to authorize a new incarnation, CAS-persisted before successor OCI effects. `StageRemoved` currently auto-rearms; the proposed controller must hold it until this fencing and transition path exists. `host_attempt`, OCI instance and desired generation are separate identities. The canonical `database_id` and numeric `shard_id` must be encoded safely into the ordered placement log and JetStream keys instead of passed through today's lowercase-token validator. TerraBase's core `ShardId::new` accepts zero and authority tests use it, but the executable `parse_local_authority_scope` rejects shard zero. Managed replication admission must require `shard_id > 0` until the TerraBase producer changes and verifies that runtime contract; the Go boundary must retain the numeric `u64` shape. The source of tenant/cluster IDs, schema catalogs and the authority signing key is a product/authority decision; Go must not sign them implicitly. TerraBase's `AuthorityPayload` builds a canonical payload for **offline** Ed25519 signing, with sorted member rows and catalog definitions; its `AcceptedAuthority::open_or_install` does not implement live membership change. The producer must supply the exact signed certificate and member TLS chain/key/roots, bind each leaf hash and failure domain to its signed row, and state how a new epoch/configuration replaces the old authority without two writers for one retained shard.

The host-facing desired state should reference an immutable, admitted artifact and a typed managed-member launch manifest bound to `(database_id, shard_id, member_id, incarnation, authority_epoch, configuration_id, volume_id, attachment_id, instance_id, host_attempt, desired_generation)`. It should name the required directory layout on one verified retained mount (`--data-dir` and separate `--replication-data-dir`), the local admin and replication addresses, the exact CLI flags, and immutable hashes of the certificate, trust roots and other nonsecret material. Secret references must resolve on the authorized host to private files with restricted ownership and permissions; their bytes do not belong in NATS desired state, environment, logs or command-line arguments. Network mode currently needs at least 4 GiB process memory and headroom of at least 1 GiB and 25% of the process limit. A member launch fails closed if the signed row, file digest, CLI identity, TLS leaf, mount or memory contract differs.

Before launch, the host must match OCI's observed instance/attachment to the registered managed host, discover the attached guest block device, verify a durable volume/filesystem identity, and mount the expected volume exclusively at a private path. It must never format or adopt a nonempty/reused volume merely because OCI says `ATTACHED`. It should prove both TerraBase directories resolve to that mount, then atomically install member-specific files and start the admitted binary. The host's signed, current-session report should carry a bounded `MountObservation` (volume/attachment, filesystem ID, mount source/target, read-write mode, observation time) and `ProcessObservation` (artifact digest, desired generation, process boot identity, cgroup/PID) so placement can reject a stale host, changed mount or wrong workload. This is **host infrastructure attestation**, not proof that TerraBase is serving or replicated.

## Requested TerraBase runtime API v1

Expose a locally authenticated, versioned control surface to the host agent (a permission-restricted Unix socket is one possible transport). The host may relay observations through its existing signed regional session; the controller must verify current session, desired generation and freshness. The exact wire encoding is for TerraBase and Go owners to agree, but the following operations and meanings are required:

| Operation | Required request/response semantics |
| --- | --- |
| `GetMemberStatus(nonce)` | Returns version, nonce, process boot ID, observation sequence/time; exact tenant/database/shard/member/incarnation; signed authority epoch/configuration/certificate hash; local storage recovery and data-plane admission state; certified peer set; per-origin durable **and applied** frontiers with the origin incarnation and epoch; bootstrap/snapshot/catch-up state; and any terminal or uncertain durability fault. A status from a raw storage or inbound-receiver-only process must say it is **not serving**. |
| `GetServingProof(expected_scope, expected_epoch, expected_config, policy)` | Returns a fresh, scope-bound decision only after the real client endpoint is admitting the declared read/write workload, replay has reached the required visibility frontier, and the declared durability/failure-domain policy is satisfied. Include the exact policy ID and frontier used. A local `/readyz`, open gRPC port, `Welcome` or `DurableAck` alone cannot satisfy this operation. If no such data-plane or policy exists, return `unsupported` and keep placement held. |
| `BeginDrain(expected_scope, expected_epoch, expected_config, operation_id)` | Idempotently rejects new client writes for this member before acknowledging the command, preserves the fence across retries/restart, and begins bounded resolution of admitted writes and replication obligations. A stale epoch/config or different operation target is rejected. This is separate from SIGTERM. |
| `GetDrainStatus(operation_id)` | Returns a fresh scope-bound **successful** receipt only after all admitted writes have resolved to the declared durable or rejected outcome, the writer is durably fenced and cannot reopen in that epoch, the required outgoing and applied frontiers are acknowledged by named surviving certified members, and the chosen durability policy says their quorum/failure domains are safe. Include survivor IDs, frontier, epoch/config, writer-fence token and receipt identity. An uncertain write, missing field or unknown outcome returns a non-successful status and keeps retirement held. |

The current bounded v1 implementation exposes `GET /v1/member/status?nonce=<128-bit hex>` only when network mode opts in with `--member-control-socket`. Its root-supervisor Unix peer check and status response provide no serving or drain proof: the response still hard-codes `receiver_only: true`, `serving: false`, and both capabilities false, while those operations return `501`. The Go host client binds this observation to the native runner's PID, process start, cgroup, socket inode and peer credentials, and compares the response with the expected signed identity and a fresh nonce. No placement or host runtime caller consumes it yet.

The separate cross-language process scenario in TerraBase `tests/support/server/member_control_managed.rs` was compile-checked with a snapshot-only Slow-suite import; that historical check is not current-source runtime evidence. The shared suite still lacks the import. A later privileged guest attempt failed during Go native `Apply` before Unix-socket verification, as recorded in the readiness plan. A successful cross-language process proof remains open.

These operations need real TerraBase producer state, not a Go-side boolean synthesized from process liveness. `ReceivedAck` is transient, `DurableAck` proves receiver append+sync, and the current receiver now emits `AppliedAck` after its applied watch advances. The outbound sender validates peer ACK context and tracks durable/applied prefixes in its stream state, but no current-source real-peer run or durable peer-acknowledgment receipt is evidenced. For serving and drain, the producer must expose sender/catch-up/apply recovery semantics and independently verifiable frontiers scoped by origin incarnation, shard and authority epoch. The controller should consume independent reports from the candidate and survivors; it cannot infer quorum or full catch-up from member count, an ACK frame alone, or a single receiver's prefix.

After `GetDrainStatus` succeeds, the host withdraws the exact desired member, requests a graceful TerraBase stop, waits for the process cgroup to empty, flushes/unmounts the verified retained filesystem, and reports a stop observation bound to host session, instance, volume, attachment, mount identity and drain receipt. The OCI `WriterStopVerifier` must validate the producer's writer-fence receipt **and** the host's no-process/no-mount observation before detach and termination. A process exit or missing cgroup alone is not a database writer-stop proof. OCI operations remain ETag/authority fenced and retain the volume. Unknown stop or unmount outcome is a hold, not a forced detach.

## State gates and real-caller acceptance

1. Keep `awaiting-runtime-contract` until v2 admission, authority package, admitted artifact, exact OCI attachment, verified guest mount and member-specific desired launch are all wired through the real controller → host agent → TerraBase binary call path. Only then enter `awaiting-healthy`; a current `running` report is insufficient.
2. Enter `serving` only with fresh host mount/process/session observations and an identity/epoch/config-matching `GetServingProof` from the actual member, checked against independent surviving members and the declared durability policy. On proof expiry, epoch change, mount change or terminal fault, leave serving and hold replacement until recovery/retirement rules permit it.
3. Before `remove-candidate`/cordon, require a certified membership-transition plan and fresh survivor serving/replication proof under the selected failure-domain policy. The TerraBase owner must define the ordering of writer fencing and authority-epoch change; before detach, the successor authority excluding the candidate must be durably accepted by survivors, and `GetDrainStatus`, exact host stop/unmount proof and OCI verifier acceptance must all hold. Test replay of every prepared stage and stale operation after controller/host/member restart.
4. Process-level acceptance should use two or more real `terrabase-server` processes, real mTLS `Replication.Sync`, an admitted client write, sender catch-up and applied visibility, then member drain and retained-volume reattachment. Assert that stale certificate, changed incarnation, wrong mount, wrong binary, stopped sender, durable-only ACK, lagged applied frontier, lost host session and SIGKILL all fail closed. Test that the signed host report and TerraBase status refer to the same desired generation and boot identity.

The current fixed two-seat topology also makes elastic scale-in within a selected region impossible: `CanBeginRetirement` requires **two other** serving members in every selected region. This is only Go's retirement safety floor, not a verified TerraBase replication factor or durability profile; the current TerraBase certificate only enforces 2–64 total members. Decide whether the product keeps that floor (allowing region removal or replacement only) or changes its topology/durability policy before implementing automatic scale-down. Neither `Replication.Sync` nor Go's current topology proves a quorum policy by itself.
