# Phase 1 budget and provider ownership property/replay shard

## Goal

Exercise the existing budget/cost and provider ownership/handoff pure cores with deterministic generated and replayed inputs. This shard strengthens caller-input capture where hostile enumeration could otherwise escape the existing fail-closed boundary.

## Scope

- At least 1,000 explicit cases per arithmetic, evidence-ordering/status, generation/ownership/fencing, permutation/culture, and handoff exactness property.
- Independent `BigInteger` budget-vector projection checks and independent expected provider authority outcomes.
- Stale, unknown, duplicate, conflicting, reordered, wrong-generation, wrong-owner, and wrong-epoch evidence.
- Construction-closed authorizing decisions and provider intents.
- Durable provider-resume authorization derived only from accepted-like evidence for an exact mutation; planned, held, rejected, and observe-only decisions cannot mint it.
- Strict, bounded, whole-file SHA-256-pinned, input-sensitive embedded replay corpus.
- Named technical snapshot bounds with maximum-plus-one handling before `Current`, defensive copies, ordinary iterator failure closure, and fatal runtime exception propagation.

## Boundary and non-claims

The technical snapshot limits are denial-of-service/input-safety bounds. They are separate from monetary bands, capacity ceilings, approval thresholds, provider quotas, or inventory policy. This shard performs no cloud/provider API, network, filesystem, process, live-price, or package-selection operation. It does not claim a cheapest provider, current cost, NATS L0/L0C evidence, deployment qualification, full-domain property coverage, mutation score, or deployment authority.
