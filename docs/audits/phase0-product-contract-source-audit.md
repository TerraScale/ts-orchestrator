# Phase 0 product contract source audit

Status: evidence inventory, not a contract freeze or cleanup authorization

Scope: `REQ-O005`, `REQ-O012`, `REQ-O016`, `REQ-O017`, and `REQ-O023`

This audit records the executable product contracts that a native orchestrator descriptor must preserve. Historical Kubernetes and Flux files are behavioral evidence only. They are not import formats or resources for adoption: the infrastructure catalog still describes Kubernetes deployments and OCI repositories for the three public services (`../TerraScale.Infrastructure/infra/regions/regions.yaml:24-29`, `../TerraScale.Infrastructure/infra/regions/regions.yaml:57-62`, `../TerraScale.Infrastructure/infra/regions/regions.yaml:91-96`), while the orchestrator work package explicitly prohibits editing sibling repositories (`docs/work-packages/phase0-source-contract-audit.md:7-11`).

## Health and observability contract

1. API readiness is stronger than process liveness. It includes product-project bootstrap and queue-replication checks tagged `ready`; `/health/ready` evaluates tagged checks while `/health/live` executes none of them (`../TerraScale.Internals/src/API/TerraScale.API/Program.cs:101-110`, `../TerraScale.Internals/src/API/TerraScale.API/Program.cs:141-149`). A native descriptor therefore needs separate readiness and liveness semantics.
2. Authentication currently registers only the shared default health check plus an otherwise empty health-check builder. Its `/health/ready` selects `ready` tags, while `/health/live` selects no checks (`../TerraScale.Internals/src/Auth/TerraScale.Authentication/Program.cs:14-25`, `../TerraScale.Internals/src/Auth/TerraScale.Authentication/Program.cs:49-56`). This means the current Authentication readiness endpoint proves HTTP responsiveness, not TerraBase/email/provider dependency readiness.
3. Dashboard's readiness and liveness routes are unconditional JSON responses (`../TerraScale.Internals/src/Dashboard/TerraScale.Dashboard.Next/app/health/ready/route.ts:1-6`, `../TerraScale.Internals/src/Dashboard/TerraScale.Dashboard.Next/app/health/live/route.ts:1-6`). AppHost dependency ordering supplies a startup gate, but the deployed readiness route does not itself validate API or Authentication.
4. Shared .NET defaults add a self liveness check, JSON logging, and OpenTelemetry metrics/traces/logs; OTLP exporters are conditional on an endpoint (`../TerraScale.Internals/src/Hosting/TerraScale.ServiceDefaults/Extensions.cs:42-69`, `../TerraScale.Internals/src/Hosting/TerraScale.ServiceDefaults/Extensions.cs:154-226`). Native workload descriptors must preserve OTLP configuration and must not infer dependency health from telemetry alone.
5. Existing Grafana is a single GRU surface backed by central and forwarded regional telemetry (`../TerraScale.Infrastructure/docs/cluster-map.md:322-329`). Current global panels derive state from Kubernetes deployment metrics and synthetic probes, for example public-service replica availability and regional API health (`../TerraScale.Infrastructure/gitops/observability/resources/production-gru/global-dashboard.yaml:237-255`, `../TerraScale.Infrastructure/gitops/observability/resources/production-gru/global-dashboard.yaml:456-456`). No exact orchestrator status projection was found in the audited product source; the target contract explicitly requires one (`ORCHESTRATOR.md:124-129`, `ORCHESTRATOR.md:182-199`). `REQ-O016` therefore requires a new sanitized typed projection/data source rather than renaming these historical metric panels.

## Release contract

The intended release contract is build once and promote exact tested artifacts. A `develop -> main` PR runs affected tests and builds in parallel; a merge to `main` promotes existing artifacts without rebuilding (`../CI_REFACTOR_PLAN.md:13-20`). The candidate record must include the Git tree, dependency snapshot, completed test inventory, platform digests, final manifest digest, and artifact hashes (`../CI_REFACTOR_PLAN.md:161-179`). Promotion must reject a mismatch, use a renewable fenced lease, publish existing artifacts, trigger reconciliation, and record resumable external-operation boundaries (`../CI_REFACTOR_PLAN.md:185-202`).

The checked-in generic workflow implements the same broad split: feature PR static/build jobs (`../TerraScale.Internals/.forgejo/workflows/ci.yml:79-103`), `develop -> main` test/build matrices (`../TerraScale.Internals/.forgejo/workflows/ci.yml:105-137`), candidate storage (`../TerraScale.Internals/.forgejo/workflows/ci.yml:139-155`), and main-push promotion from the stored manifest/bundle (`../TerraScale.Internals/.forgejo/workflows/ci.yml:157-171`). These source contracts are the input to native CI/CD. The historical `flux-*` promotion strategy strings in product descriptors remain evidence of rollout intent, not permission to retain Flux (`../TerraBase/.terrascale/deploy.json:28-29`, `../TerraScale.Internals/.terrascale/deploy.json:22-23`).
